# 알림함

- 날짜: 2026-11-26
- 상태: 개발 중
- PR: —

## 배경 (어떤 문제였나)

알림은 안드로이드 앱 푸시로만 보냈다. 서버는 알림을 저장하지 않았다.

- 웹으로만 쓰는 원우는 내 3교시에 누가 참여해도 알 길이 없었다. 상세 화면을 직접 열어 인원을 봐야 했다.
- 앱 사용자도 푸시를 놓치거나 지우면 다시 볼 곳이 없었다.

## 정한 것

### 무엇을 담나
- 푸시를 보낼 때(`PushService.send`) 같은 내용을 받는 사람마다 `notifications` 테이블에 남긴다.
  - 같은 트랜잭션이라, 롤백된 일은 알림함에도 남지 않는다.
  - 기기가 없는 웹 사용자도, 그 종류의 푸시를 끈 사람도 알림함에서는 본다. 푸시 설정은 "휴대폰 알림"만 끄는 것으로 본다.
- 담는 것: 내 3교시·참여한 3교시 소식.
  - 참여·나감, 성사, 마감 30분 전, 시간·장소 변경·취소, 빈자리, 1시간 전, 정산
- 담지 않는 것: 학교 전체에 가는 알림(새 3교시, 새 공지).
  - 피드와 공지 탭에서 이미 보이고, 사람마다 저장하면 양이 너무 많다.
- 같은 묶음(tag)의 안 읽은 알림은 새로 쌓지 않는다. 한 줄을 최신 내용으로 바꿔 맨 위로 올린다.
  - 예: "한 명이 참여했어요"가 세 번 와도 최신 인원으로 한 줄
  - 휴대폰 알림창이 같은 3교시 알림을 하나로 바꾸는 것과 같다.

### 화면
- 상단에 종 아이콘(모바일은 랭킹·관리 오른쪽, 데스크톱은 왼쪽 메뉴의 내 3교시 아래)과 안 읽은 수 배지를 둔다.
  - 웹은 1분마다, 탭으로 돌아올 때 다시 센다.
  - 앱은 푸시가 오면 바로 다시 센다.
- 알림함(`/notifications`)을 열면 모두 읽음이 되어 배지가 사라진다.
  - 이번에 처음 본 알림은 보는 동안 강조해 둔다.
  - 한 줄을 누르면 바로 그 3교시로 간다.
  - [모두 읽음]이나 한 줄씩 읽음 버튼은 두지 않는다. 열면 끝이다.
- 앱의 푸시 설정 설명에 "꺼도 알림함에는 남아요"를 덧붙였다.

### 보관
- 최근 50개를 보여 준다.
- 30일이 지나면 지운다(매일 새벽 4시 30분).
- 탈퇴하면 그 사람 알림을 모두 지운다.
- 3교시를 지우면 그 3교시로 가는 알림을 지운다. 눌러도 열 화면이 없기 때문이다.

### API
- `GET /api/me/notifications`: 최근 50개와 안 읽은 수
- `GET /api/me/notifications/unread-count`: 배지 숫자
- `POST /api/me/notifications/read-all`: 알림함을 열어 봤다

## 버린 대안과 이유

| 대안 | 버린 이유 |
|---|---|
| 웹 푸시 (브라우저 알림) | 브라우저마다 권한·지원이 달라서 손이 많이 간다. iOS 사파리는 홈 화면에 추가해야만 된다. 먼저 알림함으로 "볼 곳"을 만든다 |
| 실시간 갱신 (WebSocket·SSE) | 번개 모임이라 1분 늦어도 괜찮다. 서버 연결을 계속 붙잡을 만큼의 이득이 없다 |
| 한 줄씩 읽음 처리 + [모두 읽음] 버튼 | 클릭이 늘어난다. 알림이 하루 몇 개라서, 열어 보면 다 본 것으로 쳐도 충분하다 |
| 새 3교시·새 공지도 담기 | 학교 전체 인원만큼 줄이 생긴다. 피드·공지 탭과 겹친다 |
| 밤에 미룬 정산 알림을 알림함엔 바로 담기 | 알림을 남기는 곳이 두 군데로 갈라진다. 아침 8시에 함께 들어와도 문제없다 |

# 정산

- 날짜: 2026-11-26
- 상태: 완료
- PR: #11

## 배경 (어떤 문제였나)

3교시가 끝나면 한 사람이 계산하고, 나머지가 나중에 돈을 보낸다. 그 과정이 전부 단톡방에서 손으로 이뤄졌다.

- 총액을 몇 명으로 나눌지, 누가 안 왔는지를 계산한 사람이 직접 셌다.
- 계좌나 송금 링크를 매번 다시 올렸다.
- 누가 보냈는지 계산한 사람이 기억하고 있다가 따로 독촉해야 했다.

"얼마씩, 어디로, 누가 아직 안 보냈는지"를 3교시 화면 하나에서 끝낸다. 돈은 우리가 받지 않는다.

## 정한 것

### 흐름
1. 성사된 3교시의 모임 시간이 지나면 3교시 상세에 **정산 카드**가 뜬다. 참여자에게만, 모임 뒤 7일 동안 보인다.
2. **계산한 사람**이 [정산하기]를 누른다. 연 사람이 아니어도 되고, 참여자 누구든 된다.
   - 총액을 넣고, 안 온 사람은 체크를 푼다.
   - 1인 금액은 **100원 단위로 올림**한다.
   - 참여비가 정해진 3교시는 참여비 × 인원을 총액 기본값으로 채운다.
3. 나머지 참여자에게 "정산 요청 · 1인 33,400원" 알림이 간다.
4. 받은 사람은 [토스로 보내기] 또는 [카카오페이로 보내기]로 송금하고 **[보냈어요]**를 누른다.
   - 토스는 금액이 채워진 링크(`toss.me/아이디/금액`)로 열린다.
   - 카카오페이는 금액을 직접 넣어야 한다.
5. 계산한 사람의 화면:
   - 사람별로 보냄/아직을 본다. 현금으로 받은 사람은 직접 [받았어요]로 표시한다.
   - 안 보낸 사람에게 [다시 알리기]를 **하루 한 번** 보낼 수 있다.
6. 모두 보내면 정산이 끝나고, 계산한 사람에게 "정산 끝" 알림이 간다.

### 규칙
- 3교시 하나에 정산 하나. 나 말고 1명 이상, 총액 1,000원~300만 원.
- 아무도 [보냈어요]를 누르기 전까지만 고칠 수 있다. 그 뒤에는 취소하고 다시 만든다.
- **송금 링크**:
  - 내 정보 › 송금 링크에 한 번 저장해 두고 쓴다. 정산을 만들 때 링크가 없으면 그 자리에서 입력받아 저장한다.
  - `toss.me/아이디`와 `qr.kakaopay.com/…` 형식만 받는다. 피싱 링크를 막기 위해서다.
  - 링크가 없어도 정산은 만들 수 있다. 계좌는 단톡방에서 주고받는다.
- 계좌번호는 받지 않는다.
- 그 3교시 참여자끼리만 본다. 실명은 지금의 성사 후 공개 규칙을 그대로 따른다.
- 3교시를 지우면 정산도 지운다. 탈퇴하면 송금 링크를 지우고, 정산 기록에는 "탈퇴한 원우"로 남긴다.
- **알림**:
  - 새 종류 `SETTLE`을 추가한다. 정산 요청, 다시 알리기, 정산 끝에 쓴다.
  - 급하지 않은 알림이라 밤 12시~아침 8시에는 아침 8시로 미룬다.
- **화면**:
  - 3교시 상세의 정산 카드
  - 내 3교시 탭의 "보낼 정산" 배지와 목록
  - 내 정보 › 송금 링크
  - 알림 설정의 "정산" 항목
- **약관**:
  - 개인정보 처리방침: 수집 항목에 송금 링크(선택)를 추가한다.
  - 이용약관: "송금은 각자 앱에서 하고, 서비스는 돈을 주고받는 일에 관여하지 않음"을 추가한다.

## 버린 대안과 이유

| 대안 | 버린 이유 |
|---|---|
| 우리가 결제를 대행 | 전자금융업 등록이 필요하다 |
| 계좌번호 저장 | 민감한 금융 정보라 보관 책임이 크다. 단톡방으로 충분하다 |
| 1원 단위까지 정확히 | 보내기 번거롭다. 100원 올림이면 차이는 1인 99원 이하다 |
| 연 사람만 정산 | 실제로 계산하는 사람은 연 사람이 아닐 때가 많다 |
| 1차·2차 따로 정산 | 처음엔 하나로 시작하고, 요청이 있으면 추가한다 |
| 사람마다 다른 금액 | 화면이 복잡해진다. 1/N에 빼기만 둔다 |
| 카카오페이 링크에 금액 넣기 | 공식으로 지원하는 형식이 없다. 비공식 형식은 언제 깨질지 모른다 |

## 결과

- **백엔드**
  - DB: `V15__settlement.sql`. `settlements`, `settlement_shares` 표를 만들고, 회원에 `toss_id`, `kakaopay_url`을 더했다.
  - API: `/api/meetups/{id}/settlement` (만들기, 고치기, 취소, 다시 알리기, 보냈어요, 받았어요), `/api/me/settlements`, `/api/me/pay-links`.
  - 정산을 바꾸는 요청은 바뀐 3교시 상세를 돌려준다. 다른 3교시 동작과 같다.
  - 알림 종류에 `SETTLE`을 추가했다. 밤에 미룬 정산 알림은 `ReminderJob`이 아침 8시에 보낸다.
  - 3교시 상세의 사람 정보에 `withdrawn`을 더했다. 정산 만들 때 탈퇴한 원우를 빼려고.
- **프론트**
  - 3교시 상세의 정산 카드: 만들기 버튼, 보낼 원우 화면, 계산한 원우 화면.
  - 정산 만들기·고치기 창, 내 정보의 송금 링크.
  - 내 3교시의 "보낼 정산" 목록과 메뉴 배지, 알림 설정의 "정산" 항목.
  - 약관과 개인정보 처리방침에 정산과 송금 링크 내용을 넣었다 (11월 26일 적용).
  - `/me#pay-links`, `/me#ranking`으로 들어오면 그 칸으로 내려간다. 예전에는 내려가지 않았다.
- **테스트**
  - 백엔드 196개(새로 8개: `SettlementApiTest`), 프론트 lint, 단위 테스트 83개(새로 7개), 빌드가 모두 통과했다.
  - **화면**: 390px과 1440px, 다크 모드에서 세 화면을 직접 눌러 확인했다. 겹침이나 가로 넘침은 없고 콘솔 오류도 없다.
    - 화면: 보낼 원우, 계산한 원우, 빠진 원우.
    - 눌러 본 동작: 만들기, 고치기, 보냈어요, 받았어요, 정산 끝, 송금 링크 저장.
  - **Postgres 17**: V15가 적용됐다. 아래를 실제 서버로 확인했다.
    - 만들기, 중복 막기, 보낸 뒤 고치기 막기, 다시 알리기 하루 제한, 모두 받음.
    - 3교시를 지울 때 정산도 지워짐.
    - 밤에 미룬 정산 알림이 나감.
- **만들면서 바꾼 것**
  - 휴대폰에서 송금 버튼 높이가 24px로 줄어드는 문제를 고쳤다.
  - 계산한 원우 이름 줄에서 기수·배지를 빼고 이름만 둔다. 줄이 넘쳤다.
  - 끝난 정산에서는 다시 알리기, 고치기, 취소를 숨긴다. 기록으로만 남긴다.

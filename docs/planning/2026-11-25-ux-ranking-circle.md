# 역할별 편의성, 3교시 편의 기능, 써클, 랭킹

- 날짜: 2026-11-25
- 상태: 완료
- PR: #9

## 배경 (어떤 문제였나)

대학원장(유동준)이 요청한 네 가지에서 시작했다.

1. **개인정보 수정이 너무 멀다.** 원우는 이름·기수·학과를 아예 못 고치고, 교수·대학원장에게 요청하라는 글만 있었다.
   대학원장은 내 정보 → 관리 화면 → 원우 탭 → 본인 찾기 → 열기 → 저장, 6단계였다. 역할마다 사용자 편의성을 다시 보자.
2. **랭킹이 있으면 좋겠다.** 연합 전체·학교별, 방장·참여자 같은 카테고리로.
3. **회사명 '써클'을 넣고 싶다.** 서비스명은 안암3교시 그대로. 만든 사람 이름(유동준)을 넣을지, (주)를 붙일지.
4. **기획 히스토리를 남기자.** 해커톤처럼 기획 과정을 기록으로.

## 정한 것

### 1. 기획 히스토리
- `docs/planning/` 에 기획 한 건 = 파일 한 개. 정한 것과 **버린 대안·이유**까지 적는다
- 지난 기획(11/23~25)은 커밋·PR 기록으로 거슬러 정리
- PR 템플릿에 "기획 문서" 칸

### 2. 역할별 사용자 편의성

| 역할 | 내 이름 | 내 학과·기수 | 남의 정보 |
|---|---|---|---|
| 대학원장 | 내 정보에서 바로 | 제한 없음 | 전체, 제한 없음 |
| 교수 | 대학원장에게 요청 | 제한 없음 | 자기 학교 원우, 제한 없음 |
| 원우 | 교수·대학원장에게 요청 | 30일에 1번 | 없음 |

- 내 정보 [고치기] → 시트 한 장 (6단계 → 2단계)
- 모바일 상단 로그아웃 버튼 제거 (잘못 누르기 쉬움). 로그아웃은 내 정보에만
- 교수·대학원장: 모바일 상단에 관리 아이콘 + 처리할 신고 수
- 3교시 열기: 꼭 정할 것(제목·마실 것·시간·마감·장소)만 펼치고 나머지는 "옵션 더 보기"로 접기
- 지난 3교시 "다시 열기" (내용 복사, 시간만 새로)
- 관리: 신고 카드에서 이름을 누르면 바로 원우 관리 창

### 3. 3교시 편의 기능
- **우리 학교·기수 새 3교시 알림** (전에는 연합 새 3교시만 알렸다). 우리 기수만 3교시는 그 기수에게만
- **장소 자동완성**: 우리 학교에서 쓴 장소를 많이 쓴 순서로 추천 (외부 API 없이)
- **캘린더에 추가**: 웹은 .ics 파일(1시간 전 알림 포함) 또는 구글 캘린더, 앱은 구글 캘린더
- **빈자리 대기**
  - 정원이 차면 [자리 나면 알림] 버튼 (따로 찜 기능은 두지 않는다. 대기 신청 = 관심 표시)
  - 누가 나가거나 정원이 늘면 대기자 모두에게 알림, 먼저 누른 사람이 탄다
  - 연 사람에게는 "대기 N명" + [정원 +N] 버튼. **거절 버튼은 없다**
  - 3교시가 끝나면 대기는 조용히 사라진다

### 4. 써클 표기
- 법인 등기 전이라 **(주) 없이 "써클"**
- 첫 화면·PC 메뉴: `안암3교시 · by 써클`
- 내 정보 맨 아래: `써클 · 만든 사람 유동준 (고려대 SW·AI융합대학원 61기)`
- 개인정보 처리방침: 운영 써클, 개인정보 보호책임자 유동준 (빠져 있던 항목)
- 약관의 "돈을 받지 않는 비공식 서비스" 문구는 그대로. 유료화할 때 약관을 고치고 미리 공지

### 5. 랭킹
- 범위: 연합 / 우리 학교 / 학교 대항
- 기간: 이번 달(기본) / 전체
- 카테고리: 방장왕(성사된 3교시를 연 횟수) · 출석왕(성사된 3교시에 탄 횟수, 연 것 포함) · 성사율(3번 이상 연 사람만) · 연합왕(다른 학교 원우와 함께한 횟수)
- 학교 대항: 참여율 = 이번 달 한 번이라도 탄 원우 ÷ 가입 원우
- 이름 표시: `김*준 · 고려대 인융` (내 이름만 그대로). 상위 10명 + 내 순위
- 내 정보에 "랭킹에 안 나오기"
- 이번 달 방장왕·출석왕 1등은 이름 옆에 배지 (2번 이상일 때만)
- 집계: 성사된 뒤 모임 시간이 지난 3교시만 (열고 취소하기를 반복해 점수를 부풀릴 수 없게)

## 버린 대안과 이유

| 대안 | 버린 이유 |
|---|---|
| 원우도 이름을 직접 고치기 (30일 1번 + 변경 기록) | 학교 이메일로 본인 인증을 하고 들어온 서비스라, 이름은 고정하는 게 맞다는 대학원장 판단 |
| 정보 수정을 늘 요청 → 승인으로 | 학과·기수까지 승인을 받으면 관리자 일만 늘어난다 |
| 주간 랭킹 | 지금 규모에서는 한 주에 대부분 0~1번이라 동점만 나온다. 활동이 늘면 추가 |
| 주종별 랭킹 (소주왕 등) | 3교시 하나에 마실 것을 여러 개 고를 수 있어서 "소주왕"이 소주를 마신 횟수가 아니다 |
| 해커톤용 지표 | 필요 없음 (대학원장 판단) |
| 실명 랭킹 | 성사 전에는 이름을 가리는 서비스 원칙과 어긋난다 |
| 꼴찌·전체 순위 공개 | 창피 주기가 되지 않게 상위 10명 + 내 순위만 |
| 방장에게 참여 요청 + 수락·거절 | 거절은 "민망함 줄이기"라는 서비스 핵심과 정반대 경험이고, 방장도 부담스럽다 |
| 찜·관심 표시 따로 | 빈자리 대기 신청이 곧 관심 표시라 기능을 둘로 나눌 필요가 없다 |
| 성사 전 질문 한 줄(댓글) | 보류. 한마디·중간 합류 옵션으로 대부분 해결되고, 신고·이름 가리기·알림까지 같이 만들어야 해서 작업에 비해 효과가 작다 |
| 카카오 장소 검색 | 나중에. 카카오 키가 더 필요하다. 우선 우리 데이터로 추천 |
| 정산·결제 | 유료화할 때 함께 |
| (주)써클 | 법인 등기 전에는 상호에 회사 표시를 쓸 수 없다 (상법) |
| 만든 사람 이름 빼기 | 크레딧 한 곳 + 개인정보 보호책임자로 정리하면 깔끔하면서도 이름이 남는다 |

## 결과
- 1~5를 한 브랜치에서 한 번에 개발. DB 마이그레이션 V13 (회원 칸 2개, 빈자리 대기 테이블 1개 추가)
- 확인한 것
  - 백엔드 테스트 182개 (새로 19개: 내 정보 수정, 빈자리 대기, 랭킹, 장소 추천, 새 3교시 알림)
  - 프론트 lint · 타입 · 단위 테스트 75개 · 빌드
  - 브라우저로 폰(390px)·PC(1440px)·다크 모드에서 원우·대학원장 화면 확인
  - 실제 PostgreSQL 에서 main(V12) 데이터 위에 V13 을 올리고 새 API 확인
- 만들면서 바꾼 것
  - 빈자리 대기 카드는 꽉 찼을 때만 보인다. 자리가 남았는데도 "정원 +N" 이 보여 또 늘릴 수 있어서
  - 이름 옆 랭킹 배지는 대학원장 표시(노란색)와 헷갈리지 않게 학교 색으로
  - 앱에서는 캘린더 파일을 내려받을 수 없어 구글 캘린더 링크만 둔다. 1시간 전 알림은 웹의 캘린더 파일에만 들어간다
  - 랭킹에서도 대학원장 이름은 그대로 보인다 (원래 규칙: 대학원장 이름은 누구에게나 실명)

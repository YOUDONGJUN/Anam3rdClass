# 전체 점검 후 고친 것 (코드 · 보안 · 편의성)

- 날짜: 2026-11-26
- 상태: 개발 중
- PR: (머지 후 적기)

## 배경 (어떤 문제였나)

코드·보안·사용자 편의성 세 갈래로 전체를 점검했다. 그중 고칠 것으로 정한 항목이다.

## 정한 것

### 코드
- **앱을 공유 링크로 열면 화면을 옮길 때마다 그 링크로 되돌아가던 문제**
  - 원인: `NativeBridge`가 화면이 바뀔 때마다 앱 껍데기를 다시 켰다. 그때마다 시작 링크(`getLaunchUrl`)를 다시 열었다.
  - 앱 껍데기는 한 번만 켜고, 화면 이동은 최신 `navigate`를 ref로 쓴다.
  - 시작 링크는 앱이 켜진 동안 한 번만 연다.
- **'성사' 기준을 하나로 맞췄다**: 성사돼서 끝났고 **2명 이상** 모였을 때(`Meetup.isGatheredAt`)
  - 최소 인원 없이 열어 혼자 끝난 3교시는 후기를 묻지 않는다.
  - 그런 3교시에는 정산 버튼도 띄우지 않는다. 전에는 버튼이 떴다가 누르면 오류가 났다.
  - 대학원장 통계의 '성사' 수도 같은 기준으로 센다. 랭킹은 원래 이 기준이었다.
- **탈퇴·이용 제한 때 연 3교시를 취소하는 순서를 바로잡았다**
  - 전에는 3교시를 먼저 읽어 둔 뒤에 잠갔다. 그래서 잠근 뒤에도 예전 값이 남았다.
  - 이제는 id만 읽고 하나씩 잠가 새로 읽는다. 그 사이 연 사람이 직접 취소했으면 건너뛴다. 취소 알림이 두 번 가지 않는다.
- **알림함을 여는 순간에 온 새 알림까지 읽음으로 바뀌던 문제**
  - 읽음 요청에 '받은 목록의 가장 최근 시각'(`upTo`)을 붙여, 그때까지만 읽음으로 바꾼다.
  - 보는 동안 새 알림이 오면 종 숫자가 다시 생긴다. 그러면 목록을 다시 불러와 맨 위에 보여 준다.

### 보안
- 횟수 제한을 한곳(`RateLimits`)에서 만든다. 서버가 한 대(Render starter)라 메모리로 센다.
  - 키가 많아져도 요청마다 전체를 훑지 않는다. 1분에 한 번만 오래된 기록을 치운다.
  - 전에는 아무 이메일로나 마구 틀리면 요청마다 5천 개를 훑었다.
- 접속 IP는 Cloudflare가 넣는 `CF-Connecting-IP`로 본다.
  - 운영 응답 헤더로 Cloudflare 뒤에 있는 것을 확인했다.
  - `X-Forwarded-For`의 맨 앞 값은 사용자가 마음대로 넣을 수 있어서 쓰지 않는다.

| 막을 것 | 한도 |
|---|---|
| 한 IP에서 이메일 로그인을 몰아쳐 비밀번호 확인 자리를 다 차지 | 같은 IP에서 10분에 60번 |
| 남의 이메일로 일부러 틀려 그 사람을 잠금 | 틀린 횟수를 이메일+IP마다 센다(1시간 10번). 여러 IP에서 합쳐서는 1시간 50번. 비밀번호를 새로 정하면 풀린다 |
| 없는 주소로 인증 메일을 보내 모두의 하루 메일 한도를 다 씀 | "이메일로 시작"한 인증코드는 같은 IP에서 1시간 20번 |
| 예전 계정 잇기 비밀번호를 여러 카카오 계정으로 나눠 맞혀 봄 | 예전 아이디 하나는 하루 20번까지 틀린다(카카오 계정마다 1시간 10번은 그대로) |
| 예전 비밀번호만 맞히면 예전 관리 직책까지 이어받음 | 이을 때 직책은 원우로 둔다. 필요하면 대학원장이 다시 맡긴다 |
| 연합 3교시를 열고 지우기를 되풀이해 다섯 학교에 알림 폭탄 | 한 사람이 보내는 새 3교시 알림은 하루 3번까지. 넘으면 3교시는 열리고 알림만 안 간다 |
| 성사된 3교시에 참여했다 바로 나가며 실명·단톡방 링크 모으기 | 성사된 3교시에서 나간 기록을 남긴다(`meetup_leaves`, 30일 보관). 30일에 3번 나가면 한동안 **이미 성사된** 3교시에는 참여할 수 없다. 성사 전인 3교시는 그대로 참여한다 |
| 기수를 바꿔 가며 다른 기수 전용 3교시에 들어가기 | 원우는 가입하고 하루 안에만 기수를 직접 고친다. 그 뒤로는 교수·대학원장에게 요청한다. 학과는 지금처럼 30일에 한 번 |

### 사용자 편의성
- **정원이 찬 3교시**
  - 상태 표시를 '성사 · 마감'에서 '성사 · **만석**'으로 바꿨다. 마감이 지나 못 들어가는 3교시만 '마감'이다.
  - 상세는 '모집 마감까지' 대신 '모임까지' 남은 시간을 보여 준다.
  - 목록은 '마감 n시간 전'을 빼서 서로 부딪히지 않는다.
- **알림 메시지(토스트)**
  - 화면 위쪽에 떠서 상세의 뒤로 버튼을 3초간 덮던 것을 아래로 옮겼다(하단 메뉴·행동 바 위).
  - 메시지 위를 눌러도 뒤의 버튼이 눌린다.
- **내 3교시**
  - 고른 탭을 주소(`?tab=past`)에 남긴다. 상세에 갔다 와도 보던 탭 그대로다.
  - 상세의 뒤로 버튼 이름을 온 곳에 맞춘다: '내 3교시', '알림', '3교시 목록'. 바로 열었으면 '3교시 목록'으로 간다.
- **줄바꿈 (웹·앱 모두)**
  - 빈 화면·오류 문구는 가운데 정렬이라 줄 길이를 고르게 맞춘다(`text-wrap: balance`).
  - 목록 한 줄의 '·'는 앞에 붙는 공백을 써서 줄 첫머리에 오지 않게 했다.
  - 상세의 '…님이 열었어요'는 '연 사람' 이름표를 앞에 두고, 줄을 이름 묶음 안에서 바꾼다.
  - 내 정보 카드는 소속·학교·이메일을 아래 줄에 넓게 쓴다. 360px에서도 '61기 ·'만 남고 끊기지 않는다.
  - '교수·대학원장'처럼 '·'로 붙은 말은 '·' 뒤에서 줄이 바뀌지 않게 했다.
- **3교시 열기 오류**
  - 틀린 칸 바로 아래에 알려 준다.
  - 그 칸으로 화면을 옮기고 커서를 둔다. 접혀 있던 옵션은 먼저 펼친다.
- **누르는 영역**
  - 작게 보이는 버튼(지도 28px, 탭·작은 버튼·받았어요 36px)도 누르는 영역은 44px이다(`.hit`).
  - 모양은 그대로다.
- **기타**
  - 지운 3교시의 '취소됐어요' 알림을 누르면 내 정보 대신 3교시 목록으로 간다.
  - '귀가는 안전하게!'는 모임 당일(모임 뒤 12시간 안)에만 보인다.
  - 같은 3교시의 같은 종류 알림은 읽은 뒤에 와도 한 줄을 최신 내용으로 바꿔 안 읽음으로 올린다. '성사까지 2명' 같은 지난 숫자가 여러 줄 남지 않는다.

## 버린 대안과 이유

| 대안 | 버린 이유 |
|---|---|
| 성사된 3교시에서는 아예 못 나가게 하기 | 사정이 생긴 원우가 빠질 길이 없어진다. 횟수로 막는 것으로 충분하다 |
| 나가기를 막기 (참여 대신) | 이미 실명을 본 뒤라 소용이 없다. 대신 '이미 성사된 3교시에 참여'를 막는다 |
| 원우 기수 변경을 아예 막기 | 가입 때 잘못 고른 것을 바로잡을 길이 없다. 하루는 열어 둔다 |
| `X-Forwarded-For`로 IP 보기 | 맨 앞 값을 사용자가 바꿀 수 있어 횟수 제한을 피해 간다 |
| 횟수 제한을 DB에 저장 | 서버가 한 대라 메모리로 충분하다. 나간 기록만 30일을 세야 해서 DB에 둔다 |
| 알림 메시지를 화면 위 머리띠(안내판) 위에 띄우기 | 안내판과 같은 색이라 묻히고, 알림·랭킹 아이콘을 덮는다 |

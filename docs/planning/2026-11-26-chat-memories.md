# 3교시 톡방과 추억

- 날짜: 2026-11-26
- 상태: 완료
- PR: #24

## 배경 (어떤 문제였나)

3교시에서 이야기는 카카오톡 오픈채팅으로 했다. 연 사람이 링크를 넣지 않으면 단톡방이 없고, 링크가 있어도 성사된 뒤에야 보였다.
모임에서 찍은 사진(인생네컷 등)은 각자 카톡에 흩어졌다.

- 3교시 안에서 바로, 함께하는 원우끼리 이야기하고 사진을 주고받고 싶다.
- 모임 사진을 3교시에 남겨 두고 다시 보고 싶다.
- 새 메시지·새 사진은 알림으로 알고 싶다.
- 사진을 마구 올리면 무료 저장 용량(10GB)이 금방 찰까 걱정된다.

## 정한 것

### 톡방
- 3교시마다 하나. **지금 함께하는 원우만**(연 사람 포함) 들어온다. 참여하면 바로 들어오고, 나가거나 내보내지면 더는 못 본다.
- 이름은 3교시 공개 규칙을 그대로 따른다. 성사 전에는 서로 가려진 이름(`김*대`), 성사되면 실명.
- 이름 옆: 같은 학교 3교시는 기수 · 학과, **연합 3교시는 학교 배지**도 함께.
- 글(1000자)과 사진(한 번에 5장). 내 메시지 지우기(자리는 남고 "지운 메시지"), 신고·차단, 톡방별 알림 끄기.
- 취소된 3교시 톡방은 읽기만 된다. 카카오톡 오픈채팅 링크는 그대로 두고, 성사되면 [톡방] 옆에 [카톡 단톡방]으로 보인다.
- 대학원장도 함께하지 않은 톡방은 보지 않는다 (사적인 대화). 문제는 신고로 받는다.
- 욕설 거르기는 톡방에 걸지 않는다 (친한 사이 대화가 막힌다). 추억의 한 줄에는 건다.

### 실시간
- 서버가 한 대(Render)라 **SSE**(`/api/live`)로 "무엇이 바뀌었다"만 보내고, 화면이 API 로 다시 읽는다. 실명 규칙을 API 한 곳에서만 지키려고.
- 로그인 토큰을 머리글에 실어야 해서 EventSource 대신 fetch 로 읽는다. 화면을 안 보는 동안은 연결을 닫는다.
- 연결이 끊기면 15초마다 새 메시지를 다시 읽는다.

### 톡 알림 (`CHAT`)
- 톡방을 보고 있는 원우에게는 보내지 않는다 (화면이 읽음 표시를 보내는 동안).
- 같은 톡방은 한 사람에게 30초에 한 번만, 알림창에서는 하나로 바뀐다.
- 밤(23~8시)에는 보내지 않는다. **모임 3시간 전 ~ 6시간 뒤는 예외** — 술자리는 밤에 열린다.
- 알림함에는 쌓지 않는다. 안 읽은 수는 [내 3교시]의 톡방 목록과 하단 메뉴 배지로 본다.

### 추억
- **모였던 3교시**(성사돼서 여럿이 모였고 모임 시간이 지남)에 함께한 원우가 사진 1~5장과 한 줄을 올린다. 3교시마다 모두 합쳐 10장.
- 공개 범위: 기본은 **함께한 원우만**, 올린 사람이 고르면 **그 3교시를 볼 수 있는 원우 모두**(우리 학교 · 우리 기수 · 연합). 함께하지 않은 원우에게는 이름이 가려진다.
- 사진은 자르지 않고 보인다 (인생네컷처럼 세로로 긴 사진도 얼굴이 잘리지 않게). 칸 비율은 첫 사진에 맞춘다 (9:16 ~ 4:3).
- 새 추억은 함께한 원우에게 `MEMORY` 알림 (밤에는 알림함에만).
- 지우기: 올린 원우, 그 학교 교수, 대학원장. 신고는 3교시 신고로 받는다. 탈퇴하면 올린 추억을 지운다.
- 톡방 사진의 "추억에 올리기"로 지워지기 전에 옮겨 둘 수 있다.

### 사진 저장 (Cloudflare R2)
- 무료 10GB, 내려받는 비용 없음. 버킷은 비공개, 사진은 **서명된 주소**로만 오간다 (서버를 거치지 않는다).
- 폰에서 줄여서 올린다: 톡방 긴 변 1280px(≈200KB), 추억 2048px(≈400KB). JPEG.
- 저장 위치를 나눈다: `chat/` 은 **올린 날부터 30일 뒤** 버킷 수명 규칙이 지우고, `memories/` 는 계속 둔다.
- 제한: 한 번에 5장, 톡방은 한 사람이 하루 30장, 추억은 3교시마다 10장.
- 서명은 SDK 없이 직접 한다 (AWS Signature V4, 서버 메모리 512MB). 내 PC·테스트는 폴더 저장소로 같은 방식.

### 하단 메뉴
- 3교시 · **내 3교시(톡방 목록)** · (열기) · **추억** · 내 정보. 공지는 위쪽 머리와 피드의 고정 공지로.

## 버린 대안과 이유

| 대안 | 버린 이유 |
|---|---|
| 톡방 사진 없이 글만 | 압축·30일 삭제·장수 제한이면 용량이 거의 차지 않는다 (한 달 모임 50개 × 20장이어도 1GB 아래) |
| 톡방 사진을 "모임 30일 뒤" 삭제 | R2 수명 규칙은 올린 날 기준이다. 서버가 직접 지우면 일이 늘고 실패할 곳이 생긴다 |
| WebSocket(STOMP) | 보내기는 API 로 충분하고 받기만 실시간이면 된다. SSE 가 더 단순하다 |
| 3초마다 다시 읽기(폴링)만 | 대화가 끊겨 보이고 DB(Neon)를 계속 깨운다. 끊겼을 때의 대비로만 쓴다 |
| AWS SDK 로 R2 서명 | 서버 메모리를 많이 먹는다. 필요한 건 서명된 주소뿐이다 |
| 추억에 별점 후기를 함께 | 별점은 대학원장만 보는 익명 통계다. 공개되는 추억에 섞지 않는다 |
| 추억 사진을 4:5 로 잘라 보이기 | 인생네컷이 잘린다 |

## 결과
- 백엔드 테스트: 톡방 15개, 추억 7개, 서명 2개 (서명은 AWS 문서 예제와 같은 값)
- 화면: 톡방 · 추억 탭 · 3교시 상세의 추억 칸 · 사진 크게 보기 · 내 3교시 톡방 목록
- 세팅: R2 버킷 `anam3-photos`, CORS, 수명 규칙(`chat/` 30일), Render 환경변수 `R2_*`

## 나중에 고친 것 (2026-11-27)

- **톡방 메시지 신고에 내용이 안 남던 문제**: 교수·대학원장은 함께하지 않은 톡방을 볼 수 없어서, 사람 신고만으로는 무슨 말이 오갔는지 알 수 없었다. 이제 메시지를 신고하면 그 메시지 글(사진이면 "[사진 N장]")과 보낸 시각이 신고 기록에 남고, 관리 › 신고의 "신고 당시 내용"에 보인다. 보낸 원우가 나중에 지워도 기록은 남는다.
- **보낸 원우가 나가면 연 사람이 신고되던 문제**: 참여 번호 대신 메시지 번호로 대상을 찾는다(`chat: true`). 성사 전에 나간 원우도 그 사람이 신고·차단된다. 그 톡방에 지금 들어갈 수 있는 원우만 할 수 있다.
- 톡방에서 차단하면 그 원우의 메시지가 바로 가려진다.
- 사진 자체는 신고 기록에 남기지 않는다(톡방 사진은 30일 뒤 지워진다). 사진이 문제면 신고 설명에 적도록 한다.
- 백엔드 테스트: 톡방 신고 3개
